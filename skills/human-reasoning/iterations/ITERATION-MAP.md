## Pass catalog

| Pass | Refinement | Purpose |
|---:|---|---|
| 1 | Structural distinction | Turn a vague human–AI contrast into a concrete structural asymmetry. |
| 2 | Comparison scope | Specify which humans and which AI system are being compared. |
| 3 | Human variance | Prevent an idealized or universal human from becoming the baseline. |
| 4 | AI architecture variance | Prevent a limitation of one runtime from becoming a universal AI claim. |
| 5 | Relevance trigger | Apply the asymmetry only when it can change the decision. |
| 6 | Claim-level separation | Separate behavioral, mechanistic, functional, experiential, and normative claims. |
| 7 | Human reality field | Bind the contrast to a real person, place, time, and consequence. |
| 8 | AI comparative advantage | Use difference for complementarity rather than deficit-only imitation. |
| 9 | Evidence threshold | Make the asymmetry empirically accountable. |
| 10 | Provenance discipline | Distinguish observation, retrieval, user testimony, inference, and generation. |
| 11 | Tool and sensor compensation | Import missing contact with the world instead of narrating around it. |
| 12 | Concrete episode simulation | Test the recommendation against real execution. |
| 13 | Operational definition | Translate abstract cognitive language into observable conditions. |
| 14 | Causal mechanism | Explain why the asymmetry matters rather than merely naming it. |
| 15 | Intervention design | Prefer a discriminating action over static speculation. |
| 16 | Counterfactual test | Check whether the recommendation truly depends on the asymmetry. |
| 17 | Failure-mode hardening | Turn the identified risk into prevention, detection, recovery, and learning. |
| 18 | Adversarial framing | Stress-test the asymmetry under social and prompt pressure. |
| 19 | Power, consent, and institutional context | Account for who can speak, refuse, appeal, or be harmed. |
| 20 | Value ownership | Keep normative choices with legitimate humans and institutions. |
| 21 | Responsibility boundary | Make consequence-bearing and remedy explicit. |
| 22 | Memory and continuity | Prevent unsupported continuity and stale state. |
| 23 | Metacognitive calibration | Ground confidence outside generated self-report. |
| 24 | Explanation faithfulness | Avoid using a rationale as a privileged causal trace. |
| 25 | Prompt stability | Detect framing sensitivity and agreement pressure. |
| 26 | Complementary alternative design | Generate a serious hybrid option rather than a human-versus-AI binary. |
| 27 | Decision rule | Convert analysis into a falsifiable choice. |
| 28 | Next learning move | Attach action, signal, review, and update. |
| 29 | Positive behavioral eval | Prove the Skill invokes the control in a relevant case. |
| 30 | Negative and anti-theater eval | Prove the Skill avoids over-triggering and anthropomorphic theater. |
| 31 | Cross-track integration | Resolve dependencies and conflicts among asymmetries. |
| 32 | Minimal release gate | Retain only behavior-changing rules and close the 32×32 cell. |

## Cell lookup

For track `t` and pass `p`:

```text
new_iteration = (t - 1) × 32 + p
cumulative_iteration = 100 + new_iteration
```

Example: Track 30 (Prompt sensitivity and sycophancy), Pass 25 (Prompt stability) is new iteration `(30−1)×32+25 = 953`, cumulative iteration `1053`.
